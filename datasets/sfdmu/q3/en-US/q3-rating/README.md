# q3-rating Data Plan

SFDMU data plan for the Q3 usage rating design-time data: units, usage resources, usage policies and the
product-to-resource links (`ProductUsageResource`, PUR). The policies and grants on each PUR
(`ProductUsageResourcePolicy`, `ProductUsageGrant`) load from the sibling plan
[`q3-rating-entitlements`](../q3-rating-entitlements/README.md), which runs next. `activateRatingRecords.apex`
activates. The plan has the same shape as [`qb-rating`](../../../qb/en-US/qb-rating/README.md) (todo 319).

## Reloads: match, don't delete

Nothing in this plan uses `Insert` + `deleteOldData`. Every object is `Upsert`, `Update` or `Readonly`.

| Pass | Status objects (UnitOfMeasureClass, UsageResource, ProductUsageResource) | Why |
|------|-------------------------------------------------------------------------|-----|
| 1 | `Upsert` + `skipExistingRecords: true`, full CSV with `Status=Draft` | Inserts missing rows; never sends Status to an existing (Active) row |
| 2 | `Update` without `Status` (`objectset_source/object-set-2/`) | Corrections to the other fields still land on a reload |

PUR matches on `Product.StockKeepingUnit;UsageResource.Code`. Its pass-2 file also leaves out `TokenResource`,
which `activateRatingRecords.apex` manages. Pass 2 declares UnitOfMeasure and Product2 `Readonly` so that its
lookups resolve; without them an `Update` sends the lookup as null.

## Release 264 notes

- `RatingFrequencyPolicy.Name` is required on 264. The rows are `Daily Rating Frequency` (delay 3) and
  `Monthly Rating Frequency` (delay 0); the key is still `RatingPeriod`.
- `UsageResourceBillingPolicy.UsageAccumulationMethod` allows only `Sum`/`Peak` on 264, so the
  `DefaultUsageResourceBillingPolicy` row (`Event`, referenced by nothing) was dropped.
- The inactive `Unit` UnitOfMeasureClass had no `Type`, which 264 requires; nothing referenced it, so it was
  dropped.
