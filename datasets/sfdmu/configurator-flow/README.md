# configurator-flow Data Plan

SFDMU data plan that registers `RLM_Product_Configurator_Flow` as the org's
**default** Product Configuration Flow. Products and product classifications with
no Product Configuration Flow Assignment use the default flow, so this one record
switches the whole catalog to the RLM configurator.

`RLM_Product_Configurator_Flow` (`force-app/main/default/flows/`) is a clone of the
264 Default Product Configurator Flow (`runtime_industries_cfg__ProductConfig`
template). It differs from the template in two Product Configurator Data Manager
inputs only:

| Input | Value | Effect |
|-------|-------|--------|
| `isNonBlockingEnabled` | `true` | Attribute and option changes apply asynchronously instead of waiting on the constraint engine for each one |
| `isInstantPricingEnabled` | `true` | Instant pricing is on by default when the configurator opens |

Instant pricing also needs the org-level Instant Pricing toggle on the Revenue
Settings page, which `configure_revenue_settings` turns on in `prepare_revenue_settings`.

## CCI Integration

### Flow: `prepare_product_data`

The `insert_default_configurator_flow` step runs this plan in every build. It runs
after `deploy_full` has deployed the Flow, because the record names the Flow by API
name (`FlowIdentifier`).

### Task Definition

```yaml
insert_default_configurator_flow:
  class_path: tasks.rlm_sfdmu.LoadSFDMUData
  options:
    pathtoexportjson: "datasets/sfdmu/configurator-flow"
```

## Idempotency

The record is upserted on `FlowIdentifier`, so a rerun updates the existing record
in place rather than inserting a second one.
