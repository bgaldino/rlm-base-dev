# qb-pcm Data Plan

SFDMU data plan for the Japanese QuantumBit catalog, the `ja` counterpart of `qb/en-US/qb-pcm`. No CCI task loads it; load it with `sf sfdmu run` (or `LoadSFDMUData` with `pathtoexportjson`) before `qb/ja/qb-pricing`, on a JPY-corporate org (the `ent-sb0-jp` shape).

> **Structure follows en-US (todo 212).** Every object has en-US's operation and externalId, so a reload matches instead of duplicating. The catalog is smaller than en-US's, and its names are Japanese.

- **Component groups key on `Code`**, and `ParentGroup.Code` and `ProductComponentGroup.Code` reference them by it (a `$$` reference doesn't resolve: Bug 4).
- **Unit-of-measure classes load Draft**, as en-US's do: the platform creates a class only in Draft. `activate_rating_records` activates them; it runs in `prepare_rating` when `rating` and `rates` are on, so a ja load after the build leaves them Draft until you run it (`cci task run activate_rating_records`). The declaration has `skipExistingRecords: true`, as qb-rating's pass 1 does (qb-rating also has a pass 2 that corrects the other fields; ja doesn't): without it a reload sent `Status=Draft` and reverted the active classes (measured, todo 212). qb/en-US and q3 pcm still send it (todo 342). The cost is that a correction to an existing class's other fields doesn't land on a reload.
- **No free-trial ramp segments.** The platform rejects a FreeTrial segment until its product has a Yearly or Custom segment, and in one pass that segment doesn't exist yet. en-US carries none, so ja's two were dropped rather than given a second pass.
