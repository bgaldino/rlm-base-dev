# qb-price-revision Data Plan

QuantumBit data for **price revision**, including CPI (Price Index) (todo 314). It loads two objects:
- `IndexRate`: the yearly CPI index rates for Region `US`, which feed `Index_Rate_Decision_Table`;
- `PriceRevisionPolicy`: one Price Index policy and one Flat policy, which a rep picks on a renewal
  line or a ramp segment.

`RLM_DefaultPricingProcedure` reads both through its two Price Revision steps: the renewal step
`AdjustNetUnitPriceandSubtotalbyusingpricerevision` and the ramp step `Uplift`.

## CCI Integration

**Flow:** step 5 of `prepare_pricing_data` (when `qb=true`), task `insert_qb_price_revision_data`.
`refresh_all_decision_tables` later rebuilds `Index_Rate_Decision_Table` (it's in both the
default-pricing and the rating refresh lists). After loading outside a full build, run:

```bash
cci task run refresh_dt_default_pricing --org <alias>
```

**Other tasks:** `test_qb_price_revision_idempotency` and `extract_qb_price_revision_data`.

## Records

| Object | Name | Key values |
|---|---|---|
| IndexRate | QB US CPI 2026 … 2030 | Region `US`, `UsageType` Pricing, one calendar year each; Rate 3.2 / 3 / 2.8 / 2.6 / 2.5 (illustrative demo values) |
| PriceRevisionPolicy | QB US CPI Plus Adjustment | `PriceIndex`, Region `US`, formula `PriceIndex + PolicyAdjustment`, 2026-01-01 → 2030-12-31 |
| PriceRevisionPolicy | QB Flat Uplift | `Flat`, formula `PolicyAdjustment`, 2026-01-01 → 2030-12-31 |

`PolicyAdjustment` is the line's `UnitPriceUplift`. `PriceIndex` is the decision-table rate for the
policy's Region, on the line's date.

## Platform rules (measured on 264)

- **Region is an unrestricted picklist** with no values. The API takes any value, so `US` needs no
  Setup step. A Pricing `IndexRate` requires a Region.
- **Index rate ranges for one Region can't overlap.** The platform rejects an overlap with "Specify
  different regions or select a unique date range".
- **One policy per date range.** Two policies with the same effective dates are rejected: "The
  selected effective dates are already in use". So an org that already has a hand-made policy for
  2026–2030 rejects these rows. Remove or re-date the existing policy first.

## Measured (r1-306, fresh 264 build, procedure plan inactive)

| Case | Result |
|---|---|
| As-is renewal from 2027-05-01 of a 2,400 asset, CPI policy, uplift 2 | 2,520 = 2,400 × (1 + 3% + 2%), using the 2027 rate, applied once |
| Same renewal, Flat policy, uplift 2 | 2,448 = 2,400 × 1.02 |
| Compound group ramp from 2027-01-01 (list 3,240; segment uplift 0 / 10 / 10), CPI policy | 3,337.20 / 3,654.72 / 3,648.24. Applied % is 3 / 12.8 / 12.6: the yearly rate plus the segment's uplift, not compounded |
| Same ramp, Flat policy | 3,240 / 3,564 / 3,920.40 (compounds: 0 / 10 / 21) |

A Price Index policy on a ramp segment takes the **non-compound** path. Core makes compounding
eligible only with a Flat policy or none, so Compound has no effect under CPI.
