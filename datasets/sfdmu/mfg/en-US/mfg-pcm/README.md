# mfg-pcm Data Plan

- **No unit-of-measure classes today.** mfg's `UnitOfMeasureClass.csv` has only a header row, and mfg has no rating plan. The declaration still has `skipExistingRecords: true`, for parity with qb and q3: if classes are added, a reload of this plan won't send `Status=Draft` to a class another plan has activated. The cost is that a correction to an existing class's other fields won't land on a reload.
- **Product images need resources no build deploys.** Every `/resource/` path in `Product2.csv`'s `DisplayUrl` (FESBA_1750's included, now relative) names a static resource that ships only in `unpackaged/post_manufacturing/core_assets/staticresources/`. No `cumulusci.yml` flow loads this plan, no CCI task deploys that folder, and it is not a package directory in `sfdx-project.json`, so no CCI-built org is affected. Anyone loading this plan by hand must deploy that folder's static resources first, or the images do not resolve.
- **Still carries columns that never land on 264** (`ProductCategoryProduct.CatalogId`, `ProductRelatedComponent.ChildProductRole`, `ParentProductRole` and `UnitOfMeasureId`); dropping them is deferred to the mfg rebase (todo 332).
- **`AttributePicklist.Code` is kept**, as in qb-pcm: TSO builds require it. Default builds don't have the field (no B2B Commerce), and SFDMU skips the column there.
